REA-Video

원본의 구조와 제작 경로

샷 경계, 제작 유형, 카메라, 자막, 소리와 필요한 자산을 분석합니다. 분석 결과를 바탕으로 촬영·AI 생성·코드 제작을 선택합니다.

Hypit

편집 가능한 제작 워크플로

영상 구성과 자산을 재사용해 변형을 만듭니다. 현재 공식 문서는 생성 모델 없이 자막·모션그래픽·코드 영상을 렌더하는 경로도 설명합니다.

REA-Video 분석만으로 완성 영상이 자동 보장되지는 않습니다. AI 샷 자동 생성은 별도 도구·계정이 필요하고, 코드 샷의 Remotion 프로젝트는 에이전트가 따로 작성합니다. [S2] [S5] [S7]

영상의 숫자는 이렇게 해석하세요

시연 표현실무에서의 해석
보름 / 별 9천 개영상 제작 당시의 인기 지표. 현재 값이나 품질 보증이 아닙니다.
60초 영상 → 1분 분석시연 환경의 사례. 해상도·OCR·음성 분리·모델 호출·첫 다운로드에 따라 달라집니다.
모델 468MB영상 당시 구성. 현재 CLI 문서는 음성/음악 분리 약 67MB, SFX 분리 약 149MB, 한국어 OCR 약 14MB 등 개별 다운로드를 안내합니다. 고정 총용량으로 보지 않습니다.
약 320크레딧 / 1080p해당 캐릭터 시트·재시도·생성 사례의 합계. 다른 계정·모델·시점의 견적에 그대로 적용하지 않습니다.
3D 생성 크레딧 0영상 생성 API를 쓰지 않았다는 뜻. 코딩 에이전트·TTS·음원·컴퓨팅 비용까지 0이라는 뜻은 아닙니다.

02

설치와 첫 분석

처음에는 10–15초 구간 1개로 시작하세요. 이는 이 가이드의 실무 권장값입니다. 짧은 구간으로 환경과 판정을 확인한 뒤 전체 영상으로 확장하면 재작업을 줄일 수 있습니다.

필수 준비

명령을 실행할 수 있는 Claude Code 또는 Codex, Python 3.10 이상, ffmpeg·ffprobe, 레퍼런스 MP4/MOV. 분석 결과를 저장할 여유 공간도 확보합니다.

선택 준비

영상·이미지 이해가 가능한 모델, 실제 영상 생성 계정, TTS. 기본 도구 분석과 의미·운동 검수는 다릅니다. 설치만으로 모든 역프롬프트가 확정되는 것은 아닙니다.

이 페이지의 ‘복사’ 버튼은 명령을 실행하지 않습니다. 복사한 프롬프트를 Claude Code/Codex 작업 창에 붙여넣으면 해당 에이전트가 작업합니다.

가장 쉬운 설치 요청

https://github.com/JuneYaooo/rea-video 의 최신 README와 설치 스크립트를 읽고, 내 OS에 맞게 설치해줘. Python 3.10 이상과 ffmpeg·ffprobe를 점검하고 기존 설치를 보존해. CLI와 에이전트 스킬 연결을 각각 검증한 뒤 rea-video --help의 실제 실행 결과를 알려줘. 아직 유료 API는 호출하지 마.
macOS / Linux · 명령어로 설치
# 새 작업 디렉터리에서 실행. ffmpeg·ffprobe와 Python 3.10+가 필요합니다.
git clone https://github.com/JuneYaooo/rea-video
cd rea-video
python3 -m venv .venv
source .venv/bin/activate
bash scripts/install_skill.sh
rea-video --help

공식 스크립트는 CLI 설치와 에이전트 스킬 연결을 처리합니다. ffmpeg가 없으면 경고하므로 실제 실행 가능 여부를 별도로 확인합니다. 기존 폴더가 있다면 덮어쓰지 말고 설치 프롬프트로 점검하세요. 설치 스크립트

Windows PowerShell · CLI 수동 설치
# Git, Python 3.10+, ffmpeg·ffprobe가 설치된 PowerShell에서 실행합니다.
git clone https://github.com/JuneYaooo/rea-video
cd rea-video
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[ocr]"
# 공식 CLI 문서의 OpenCV 충돌 정리. 이 프로젝트 가상환경에만 적용합니다.
.\.venv\Scripts\python.exe -m pip uninstall -y opencv-python
.\.venv\Scripts\python.exe -m pip install --force-reinstall --no-deps "opencv-python-headless>=4.8,<5"
.\.venv\Scripts\rea-video.exe --help

이 명령은 CLI 설치입니다. 스킬 등록은 01번 프롬프트로 사용하는 에이전트의 경로에 맞춰 별도로 처리합니다. Windows에서 bash 스크립트를 PowerShell 명령처럼 실행하지 않습니다.

한국어 자막을 포함한 기본 분석

# 입력 영상을 현재 폴더의 ref.mp4로 준비한 뒤 실행합니다.
# ko는 자막 OCR 언어, en은 보고서 언어입니다.
rea-video decompose ref.mp4 -o out/ref --lang en --ocr-lang ko
rea-video summary out/ref/breakdown.json
rea-video videomd out/ref --check
--lang ko와 --ocr-lang ko는 다릅니다. 확인한 CLI 보고서 언어는 zh/en이며 한국어 자막 OCR은 ko를 지원합니다. 원본 보고서는 지원 언어로 만들고 한국어 설명은 에이전트가 별도 요약하게 하세요. 한국어 내레이션의 ASR 검수는 OCR과 별도입니다.

03

보고서는 이 순서로 읽기

  1. report.html — 사람을 위한 전체 지도

    샷 시간표, 제작 유형, 신뢰도와 준비 자산을 확인합니다. 신뢰도는 판단의 확신 정도이지 ‘원본 제작자가 실제로 쓴 도구’의 증명이 아닙니다.

  2. VIDEO.md — 에이전트의 시작점

    작은 카드 → 개요 → 타임라인 → 필요한 샷 파일 순서. 원시 JSON 전체를 한 번에 넣을 필요가 없습니다.

  3. storyboard·샷 프레임 — 눈으로 재검수

    첫·중간·끝을 비교합니다. 카메라가 뒤로 이동하는지, 피사체만 작아지는지, 장면이 실제로 끊기는지 확인합니다.

  4. 제작 계획 — 샷과 호출을 구분

    샷 하나가 꼭 생성 한 번은 아닙니다. 같은 공간의 연속 샷을 묶을 수 있지만 모델의 실제 길이·참조 지원을 먼저 확인합니다.

실무 표의 열기록할 내용
ID · 시간shot_001 / 시작 / 끝 / 길이. 초 또는 프레임 단위를 명시.
관측 / 추정화면에 보인 것과 ‘AI 같다’는 판단을 분리. VIDEO.md의 ~ 표시는 추정 필드.
카메라시작 구도, 이동 방향, 속도 변화, 끝 구도, 추적 대상.
자산·연속성인물/제품 ID, 시작·끝 참조, 의상·색·위치의 고정 조건.
소리·글자음성/BGM/SFX, 자막 시작·끝·위치·스타일, 실제 beat 시점.
제작 경로AI 생성 / 3D·코드 / 촬영 / 화면 녹화 / 혼합과 검수 항목.
영상 사례의 중요한 교훈: 처음 ‘고정’으로 해석된 카메라를 실제 프레임 확인 뒤 후진 추적으로 수정했습니다. 보고서를 바로 정답으로 쓰지 말고 카메라와 인물 동작부터 재확인하세요.

S1S6

04

영상 종류마다 제작 경로가 다르다

AI / IMAGE → VIDEO

캐릭터 일관성을 먼저, 고해상도는 나중에

참조 시트생성 단위 설계초안연속성 검수확정·합성
  1. 필요한 이미지부터 목록화

    REA-Video가 인물 이미지를 직접 모두 만들어주는 것은 아닙니다. 같은 인물의 뷰·의상·표정을 자산 ID로 고정합니다.

  2. 모델의 실제 지원 확인

    영상에 나온 Higgsfield/Seedance 구성은 시연 선택입니다. 현재 계정에서 쓸 수 있는 모델·참조 수·길이·해상도로 계획을 다시 계산합니다.

  3. 움직임을 시간순으로 작성

    시작 구도 → 주체 행동 → 카메라 이동 → 끝 상태. 연속 장면은 앞 클립 끝 프레임을 다음 클립 참조로 활용할 수 있는지 확인합니다.

  4. 초안의 실패한 샷만 수정

    업스케일로 디테일이 번지면 고해상도 재생성과 비교합니다. 자막은 영상 모델에 그리게 하지 말고 후반에서 합성합니다.

자동 생성 연결은 capsule-cinema를 선택적으로 사용합니다. dry-run 이후 실제 유료 호출을 구분하세요. S5

THREE.JS + REMOTION

3D 공간과 시간표를 코드로 설계

새 대본내레이션샷·시간표장면·카메라정지화면 검수렌더

2D 캐릭터를 카드처럼 세우고, 3D 바닥·건물·소품 사이로 카메라를 이동시키는 방식입니다. 모든 오브젝트가 정교한 3D 모델이어야 하는 것은 아닙니다.

  1. 템플릿 설치와 요구사항 구분

    claude-animated-shorts는 ~/.claude/skills/cartoon-3d-short/에 배치하며 Node·Python·ffmpeg·Remotion·@remotion/three가 필요합니다. 예제의 영어·자막 없음·길이는 내 작업 설정과 별개입니다.

  2. 보이스를 먼저 확정

    말 길이가 컷 길이를 결정합니다. 내레이션이 바뀌면 장면과 자막 타이밍도 재정렬합니다.

  3. 프레임에 고정된 카메라와 동작

    카메라 위치/대상/FOV, 피사체 이동, 보간 곡선을 같은 시간축으로 구성합니다. 주요 프레임부터 렌더해 가림·깊이·가독성을 확인합니다.

  4. 렌더·저장공간·비용 검토

    최종 렌더 전 해상도를 낮춘 테스트를 합니다. 템플릿은 REMOTION_TMP 여유 공간을 강조합니다. 영상 API 크레딧 0과 전체 제작비 0을 구분합니다.

LIVE / HYBRID

촬영할 것과 생성할 것을 먼저 분리

인터뷰, 실제 제품 사용, 화면 녹화처럼 원본 증거가 필요한 샷은 직접 확보합니다. 설명 타이포·추상 도형·배경 연출은 코드 또는 AI 경로로 제작할 수 있습니다.

  1. 촬영 계획

    촬영 장소·장비·카메라 높이·주광 방향·피사체 위치·필요 테이크를 목록화합니다. 정확히 측정되지 않은 값은 추정으로 표시합니다.

  2. 자료 수집

    제품 사진·공식 정보·실제 화면 녹화·내레이션을 받습니다. 누락된 샷은 명시적인 내부용 플레이스홀더로만 관리합니다.

  3. 최종 조립

    촬영·생성·코드 결과를 같은 해상도와 프레임레이트로 맞춥니다. 배포본에는 미완성 원본 대체 샷이나 허가 없는 음원을 남기지 않습니다.

같은 영상에서도 샷별로 경로가 달라질 수 있습니다. 예: 실제 제품 촬영 + AI 분위기 컷 + 코드 가격 카드 + 음성 설명. S2 S5 S8

막히는 지점별 해결
URL을 넣었는데 분석이 시작되지 않음
페이지 주소와 영상 파일은 다릅니다. 다운로드 단계가 성공했는지, 실제 재생 가능한 파일이 있는지 먼저 확인합니다. 정상 확보한 로컬 MP4로 입력을 고정하면 분석과 다운로드 오류를 분리할 수 있습니다.
첫 실행이 오래 걸림 / 모델 다운로드 실패
모델 다운로드·CPU 음성 분리·OCR을 구분해 로그를 확인합니다. 저장공간과 네트워크, Python 의존성 문제를 해결한 뒤 같은 폴더에서 재개합니다. ‘1분 완료’ 사례를 고정 제한시간으로 두지 않습니다.
한국어가 깨지거나 옵션 오류가 발생
자막은 --ocr-lang ko, 원본 보고서는 --lang en 또는 zh입니다. 한국어 설명은 별도로 요청합니다. 음성 인식의 잘못된 고유명사는 실제 오디오를 듣고 교정합니다.
프롬프트가 빈약함 / 카메라가 다름
기본 도구 분석과 의미 분석을 구분합니다. VLM이 전부 실패하면 켠 것처럼 보이더라도 실질적으로 미사용 상태일 수 있습니다. 실제 프레임을 보는 에이전트로 review하고, 시작·중간·끝의 관계로 이동을 다시 작성합니다.
인물이 바뀌거나 두 클립이 끊어져 보임
자산 ID, 의상, 머리색, 구도, 마지막 프레임 연결을 점검합니다. 여러 변수 중 하나씩 고치고 실패한 생성 단위만 재시도합니다.
3D 렌더가 멈추거나 저장공간이 부족
예제 전체 자산의 복사량과 REMOTION_TMP 위치를 확인합니다. 짧은 구간·낮은 해상도 테스트 후 최종 렌더합니다. 실제 에러 로그를 기준으로 의존성, 브라우저 렌더, 메모리 문제를 구분합니다.
음악 BPM은 같은데 움직임이 안 맞음
곡의 시작 오프셋, 실제 beat/onset, 전환 지점을 확인합니다. BPM만으로 곡의 첫 박자나 강박 위치가 자동 확정되지 않습니다. 같은 타임라인에서 오디오와 프레임을 함께 평가합니다.
